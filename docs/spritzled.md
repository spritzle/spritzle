# spritzled - Spritzle Daemon

`spritzled` is the daemon service for Spritzle. It manages the underlying [libtorrent](https://libtorrent.org) session, manages torrent state and resume data, handles the hook alert dispatch system, and exposes an HTTP REST API for clients (such as the `spritzle` CLI or web interfaces).

## Usage

```shell
spritzled [OPTIONS] [COMMAND] [ARGS]...
```

### Options

* `-p, --port INTEGER`: Port for the HTTP REST server to listen on (default: `8080`).
* `-c, --config-dir, --config_dir PATH`: Path to the configuration directory (default: `~/.config/spritzle`).
* `-l, --log-level [DEBUG|INFO|WARNING|ERROR]`: Daemon log verbosity (default: `INFO`).
* `--debug`: Enable asyncio event loop debug mode.
* `--help`: Show the help message and exit.

### Subcommands

#### `spritzled token`

Generates an authentication JWT token directly from the daemon configuration without requiring the daemon to be running or exposing the admin password.

```shell
spritzled token [OPTIONS]
```

Options:
* `-c, --config-dir, --config_dir PATH`: Path to the configuration directory.
* `-e, --expires-in FLOAT`: Token lifetime in seconds (e.g. `3600` for 1 hour; `0` for no expiration). Defaults to `auth_timeout` from config (default: 120 seconds).

**Example:**

```shell
# Generate a token valid for 24 hours
$ spritzled token -e 86400

```

## Configuration & Storage

By default, all runtime configuration and persistent state are stored in `~/.config/spritzle/` (or the directory passed via `-c / --config-dir`).

### File Layout

* `config.db`: An SQLite database containing persistent daemon configuration settings and custom torrent metadata (e.g. tags).
* `spritzled.lock`: An exclusive file lock (`flock`) created when the daemon starts to ensure only one instance runs per configuration directory.
* `session.state`: Bencoded libtorrent session state, restored when `spritzled` starts and updated upon clean shutdown.
* `resume_data/`: Directory storing `.fastresume` metadata files for each active torrent, named by its 40-character hexadecimal info-hash.
* `hooks/`: Directory containing user-defined hook executables triggered by libtorrent alerts. See [hooks documentation](hooks.md) for details.

### Key Configuration Settings

Configuration values can be inspected or modified at runtime via the REST API (`/config`) or using `spritzle config`.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `auth_secret` | string | *(auto-generated)* | 256-bit secret used to sign and verify JWT authentication tokens. |
| `auth_password` | string | `""` | Password required to obtain an auth token via `POST /auth` (or `spritzle auth`). |
| `auth_timeout` | float / int | `120` | Expiration lifetime (in seconds) of tokens generated by `POST /auth`. |
| `auth_allow_hosts` | list[str] | `["127.0.0.1", "::1"]` | IP addresses allowed to access the REST API without authentication. |
| `listen_interfaces` | string | `"0.0.0.0:6881"` | libtorrent network interfaces and ports to bind to. |
| `save_resume_data_interval` | int | `60` | Interval in seconds between automatic background resume data flushes. |

## Running as a Systemd Service

To run `spritzled` as a user service under systemd, create `~/.config/systemd/user/spritzled.service`:

```ini
[Unit]
Description=Spritzle BitTorrent Daemon
After=network.target

[Service]
Type=simple
ExecStart=%h/.local/bin/spritzled --config-dir %h/.config/spritzle --port 8080 --log-level INFO
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```

Enable and start the service:

```shell
systemctl --user daemon-reload
systemctl --user enable --now spritzled
```

Check service status and logs:

```shell
systemctl --user status spritzled
journalctl --user -u spritzled -f
```
